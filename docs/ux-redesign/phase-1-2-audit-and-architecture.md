# ShipAudit Pro — Full UX/UI Redesign

التاريخ: 2026-09-04  
الحالة: Phase 1 (Audit) وPhase 2 (UX Architecture) معتمدان كأساس التنفيذ  
النطاق: طبقة العرض وهندسة المعلومات فقط. لا تغيير في Business Logic أو APIs أو Database أو Permissions.

## 1. الخلاصة التنفيذية

ShipAudit منصة تشغيل وقرار تجمع بيانات Zoho Books ولمحة وHatif/WhatsApp/IVR والبنوك وشركات الشحن. المشكلة ليست نقص وظائف؛ المشكلة أن الوظائف نمت داخل أغلفة وتنقلات وطبقات CSS متعددة، فصار الوصول إلى النتيجة يعتمد على معرفة المستخدم بتاريخ النظام.

القرار التصميمي الجديد:

- ثمانية Workspaces رئيسية فقط: الرئيسية، العملاء، المبيعات، الحملات، المالية، التشغيل، التقارير، الإدارة.
- المسار الرئيسي يعبّر عن مجال العمل، لا عن جدول أو تكامل أو نوع ملف.
- التفاصيل تنتقل إلى Tabs وFilters وContext menus وCommand menu داخل مساحة العمل.
- Customer 360 وCarrier 360 هما صفحتا الكيان الأساسيتان؛ لا يتكرر ملف الكيان في نوافذ وصفحات متباعدة.
- الصفحات القديمة تبقى كـdeep links وaliases محمية بالصلاحيات حتى اكتمال الترحيل، لكنها لا تصبح عناصر رئيسية.
- فتح الشاشة أو المعاينة لا ينفذ كتابة أو إرسالًا. كل إجراءات المخاطر تبقى خلف الحواجز الحالية.

هذا القرار يحدّث عقد المراكز السبعة السابق بإضافة **الحملات** كمركز مستقل بناءً على قرار المنتج الصريح في طلب إعادة التصميم الحالي.

## 2. منهج التدقيق

تمت مراجعة:

- `src/App.jsx`: المسارات، الحراس، PageSlot keep-alive، إعادة التوجيه، App Shell.
- `src/lib/navigation.js` و`src/lib/pageTitles.js`: IA الحالية والأسماء الظاهرة.
- كل ملفات `src/pages/*.jsx` (64 ملفًا) وكل مكونات `src/components`.
- تعريفات Tabs وViews وModals وDrawers وعمليات الكتابة المستدعاة من الواجهة.
- طبقات CSS المستوردة من `src/main.jsx` وكل CSS داخل `src`.
- عقود المنتج والاختبارات، خصوصًا Customer 360، التحصيل، Zoho، دورة المحاسب، الأتمتة، RTL والجوال.

## 3. الوضع التقني الحالي

| البند | الواقع الحالي | الأثر على إعادة التصميم |
|---|---|---|
| الواجهة | React 18 + Vite 5 + React Router | نحافظ على الإطار ونفصل الغلاف عن الصفحات تدريجيًا |
| التنقل | `App.jsx` يستخدم شروط `PageSlot` أكثر من `<Route>` فعلية | يجب إنشاء Registry واضح للمسارات بدل استمرار شروط موزعة |
| الصلاحيات | `PATH_PERM` و`permKey` و`permAny` و`adminOnly` | تبقى الحراسة كما هي وتنتقل إلى تعريف Route مركزي |
| البيانات | Services في `src/lib` مع بعض الجلب داخل الصفحات | لا تغيير للعقود؛ Presentation فقط |
| الحالة | Local state + URL state + keep-alive PageSlots | نحافظ على URL state ونقلل التركيب الدائم حيث يمكن دون كسر التدفقات |
| CSS | 34 ملفًا، 17,810 سطرًا، 2,731 `!important`، 1,542 لون hex، 167 media query | Design System جديد ذو namespace واضح؛ تنظيف القديم في Phase 7 فقط |
| المكونات | `UI.jsx` كبير + عدة primitives محلية ومتكررة | إنشاء primitives مؤسسية صغيرة، ثم adapters للصفحات القديمة |
| RTL | `direction: rtl` عام مع `direction:ltr` موضعي للأرقام | نحتاج primitives للأرقام/المال/المعرفات بدل إصلاحات صفحة بصفحة |

## 6. جرد النوافذ والـDrawers

النظام يملك أكثر من 45 سطحًا حواريًا. أهم العائلات:

| العائلة | النوافذ الحالية | قرار التوحيد |
|---|---|---|
| العميل | Customer drawer بأكثر من تنفيذ، Customer Context Drawer، ملف متابعة، Store 360 | Store 360 صفحة كاملة؛ Drawer معاينة مختصر واحد فقط |
| التحصيل | مهمة تحصيل، وعد دفع، تأجيل، شطب، مراجعة شطب، تطبيق أرصدة | Drawer للمهمة؛ Dialog للتأكيد/الكتابة المالية |
| المبيعات | متابعة، نتيجة، Lead، Deal، اكتشاف هدهد، رفع Leads، إسناد جماعي | Drawer لسجل الفرصة؛ Dialog للإنشاء/الرفع/الإسناد |
| الحملات | WhatsApp، IVR، نتيجة الحملة، حملة حية، مراجعة bulk | Flow واحد: جمهور ← حماية ← معاينة ← إطلاق ← نتيجة |
| الناقل | ربط Zoho، دفع/نزاع/ربط مراجعة، رفع كشف، مطالبة | Drawer لسياق العملية وDialogs للمخاطر |
| البنك/Zoho | حذف، ملاحظة، تصنيف، مطابقة، مراجعة عمليات، تصدير النقص، ربط حساب | Drawer لمراجعة العملية وDialog للكتابة/الحذف |
| الإدارة | موظف، صلاحيات، نشاط، حذف؛ عقد وناقل | Dialog موحد مع FormSection وDanger confirmation |
| التشغيل | نوع ملف غير معروف، رفع مجمع، حذف ملف، مهمة متكررة، إقفال/فتح فترة | Dialog قياسي مع حالة نتيجة واضحة |

مشاكل مثبتة:

- يوجد أكثر من تنفيذ لمعاينة العميل (`CustomerDrawer`, `AccountDrawer`, `CustomerContextDrawer`, Store 360 داخل مسار الدليل).
- بعض المودالات تحمل Emoji كأيقونة وعنوان؛ هذا غير متسق مع الطابع المؤسسي الجديد.
- `Drawer` و`Modal` اسمان غير دقيقين أحيانًا؛ بعض الـDrawers مبنية فعليًا على `Modal` عريض.
- إجراءات خطرة موزعة بين `window.confirm` و`Modal` مخصص؛ تحتاج `ConfirmDialog` واحدًا.

## 7. جرد الوظائف والإجراءات

لا تُحذف أي وظيفة. يعاد تجميعها كالتالي:

### 7.1 العملاء وCustomer 360

- البحث بالاسم ورقم المتجر والجوال، وفتح Customer 360.
- عرض مصدر البيانات وحداثته ومزامنة Zoho عند الصلاحية.
- عرض الحالة التشغيلية، المتاجر المرتبطة، الشحنة الأخيرة، المحفظة والذمم.
- عرض الفواتير، الدفعات، المستحق والمتأخر، الرصيد الافتتاحي والائتمان غير المستخدم.
- عرض الشحنات والناقلين والتواصل والـtimeline.
- تسجيل متابعة مبيعات أو نتيجة تواصل أو وعد تحصيل.
- إنشاء جمهور حملة من سياق مالي/تشغيلي.
- فحص حساب لمحة وتشغيله/إيقافه مع القراءة قبل وبعد والاعتماد الصريح.
- فتح المطابقة أو مركز الناقل من سجل العميل.

### 7.2 المبيعات

- قائمة العمل اليومية وترتيب الأولويات.
- إدارة عملاء منصة لمحة ومراحل المتابعة والمالك والموعد التالي.
- إدارة العملاء الخارجيين ورفعهم وتنظيفهم وإسنادهم جماعيًا.
- اكتشاف هدهد واعتماد/رفض المرشحين.
- إنشاء Lead/Deal/Task وإغلاق الفرصة كفوز أو خسارة مع السبب.
- متابعة تفعيل المتاجر وحركة النشاط والنمو.
- قراءة مرجع Hatif دون تحويل الرد تلقائيًا إلى Lead.

### 7.3 الحملات

- بناء الجمهور من مصدر محدد أو Segment أو ملف خارجي أو handoff من التحصيل.
- تطبيق هوية الجوال السعودية ومنع التكرار واستبعاد عميل لمحة من الجمهور الخارجي.
- اختيار WhatsApp أو IVR أو تصدير/مهام بحسب الصلاحية.
- التحقق من حداثة المصدر والقالب والهوية والحظر وتعارض 24 ساعة وحالة النتيجة السابقة.
- حفظ مسودة ومراجعة preflight ثم إطلاق صريح.
- عرض نتائج القنوات، جودة القوالب، الرسائل، أثر التحصيل ونشاط فريق هاتف.
- إدارة blocklist والقوالب والأهداف والتاقات في الإدارة لا في التشغيل اليومي.

### 7.4 المالية

- قراءة ذمم العملاء الحية وأعمار الفواتير والرصيد الافتتاحي منفصلًا.
- البحث والفلترة والـbulk selection والإسناد في قائمة التحصيل.
- تسجيل/إكمال/كسر الوعد وتأجيل المهمة وتغيير المرحلة وطلب الشطب واعتماده/رفضه.
- تخطيط وتطبيق الأرصدة الدائنة خلف صلاحية المدير وحارس idempotency.
- قراءة البنوك، استيراد كشف محلي، تصنيف العمليات، الملاحظات، المطابقة والحذف المحمي.
- تصدير ملف النقص لرفعه يدويًا في Zoho؛ لا رفع كشف إلى Zoho.
- مراجعة COD التاريخي ودفعات الناقلين.
- عرض Zoho: فواتير العملاء، دفعاتهم، الموردون، الفواتير، أوامر الشراء، المصروفات، الاعتمادات، الأصناف، البنوك، القيود ودليل الحسابات.
- مزامنة Zoho، تنزيل PDF/مرفق، finalize/send/ZATCA بحسب الصلاحية.
- مطابقة العملاء والموردين وربط السجلات ورفع/حذف snapshots واستيراد افتتاحيات موثقة.
- قائمة الدخل، أعمار النقد، توقع السيولة وإقفال/فتح الفترات.

### 7.5 التشغيل

- تعريف الناقل وعقده وأسعاره ونوع ملفه وجدول الاستلام.
- استقبال الملفات واكتشاف النوع والناقل والتحويل لمسار الفاتورة الصحيح.
- تحليل ملف التدقيق، عرض الفروقات، الاعتماد أو الرفض مع الإثبات العقدي.
- عرض الشحنات وAWB، تصدير الأوزان، استيراد شحنات لمحة ومطابقة الاكتمال.
- إدارة مطالبات الناقل وحالات الاسترداد.
- دفتر الناقل: الربط بالمراجعة، التسديد الفردي والجماعي، النزاع وسجله.
- كشوف الناقلين والرفع والربط.
- دورة المحاسب الشهرية ومراحلها وموانع الإقفال.
- مهام الناقلين والجداول المتكررة ومواعيدها الصريحة.
- فوترة التجهيز والأوزان الزائدة وسجل التصدير والإلغاء المحمي.

### 7.6 التقارير والإدارة

- إنشاء التقارير الرسمية والشهرية وتقارير Zoho والمطابقة وSOA.
- سجل الصادرات وإعادة تنزيل الملف الأصلي.
- أداء الناقلين والأسعار وأثر الحملات والتواصل.
- إدارة الموظفين والصلاحيات وسجل النشاط.
- إدارة التكاملات والمصادر وWebhooks وسلامة البيانات.
- إدارة الأتمتة: عرض القواعد، preview، التشغيل الصريح المسموح، سجل النتائج.
- إعداد القنوات والذكاء الاصطناعي والبيانات والعقود.

## 9. صفحات تدمج وصفحات تصبح ثانوية

### لا تحتاج عنصرًا رئيسيًا

- كل callbacks والنتائج المؤقتة: `/zoho-callback`, `/results`, `/upload`.

## 11. Navigation contract

### Desktop

- Sidebar ثابت بعرض 224–240px، ثمانية مراكز فقط.
- Top Header: Breadcrumb، عنوان الصفحة، البحث العام، الإجراء الرئيسي، المستخدم.
- Workspace sub-navigation داخل منطقة المحتوى؛ ليست Sidebar ثانية.
- Command Menu يصل لكل المسارات الثانوية والكيانات والإجراءات المصرح بها.
- المستخدم يرى بوضوح: المركز ← العرض ← الكيان.

### Mobile

- Bottom navigation: الرئيسية، العملاء، المبيعات، المالية، المزيد.
- «المزيد» يفتح قائمة واحدة للتشغيل والحملات والتقارير والإدارة؛ لا Drawer مكرر مع نفس العناصر الموجودة في Bottom bar.
- داخل Workspace تستخدم قائمة «طريقة العرض» أو tabs قصيرة قابلة للوصول، لا صفًا عريضًا يكرر كل الصفحات.
- الصفوف تصبح Compact record views؛ التفاصيل عند الفتح، ولا تتحول كل قيمة إلى Card.

## 12. Design principles الملزمة للمراحل التالية

- Financial/Operations Backoffice: كثافة متوسطة، surfaces مفتوحة، جداول أولًا.
- Brand color واحد. الأحمر والأخضر والبرتقالي دلالية فقط.
- Radius منخفض، ظلال شبه معدومة، بلا gradients وglassmorphism.
- Primary action واحد لكل context؛ secondary محدود؛ النادر داخل overflow.
- كل click على رقم/تنبيه يفتح Result Set مفلترًا قابلًا للمراجعة.
- حالات loading/empty/error/stale/permission جزء من primitive وليست CSS خاصًا بكل صفحة.
- لا حذف CSS قديم قبل اكتمال migration وإثبات عدم وجود references.

## 13. متطلبات RTL والأرقام

- `html` وApp Shell يحملان `dir="rtl"`، بينما المعرّفات التقنية وAWB والإيميل وURL تستخدم `dir="ltr"` مع `unicode-bidi:isolate`.
- كل قيمة مالية تستخدم primitive واحدًا يضع الرقم والعملة في كتلة غير قابلة للتفكك:

  ```html
  <span class="money" dir="ltr"><bdi>69,474.58</bdi>&nbsp;<bdi>ر.س</bdi></span>
  ```

- الأرقام `en-US`/`latn` مع `font-variant-numeric: tabular-nums`، من دون فرض LTR على الخلية كاملة.
- Breadcrumb chevrons وpagination arrows تعتمد logical direction لا رموز نصية.
- Inputs المالية والهواتف والمعرفات تعلن اتجاهها محليًا؛ labels تبقى RTL.

## 14. بوابة الانتقال إلى Phase 3–5

لا يبدأ ترحيل بقية الصفحات قبل تحقق الآتي في الشاشات المرجعية:

- App Shell الجديد يعمل بالصلاحيات والمسارات القديمة.
- Tokens وprimitives مركزية بلا CSS صفحة جديد إلا للتركيب الخاص.
- الرئيسية ليست شبكة KPI cards وتفتح Result Sets حقيقية.
- العملاء Data Table/compact rows وتفتح Customer 360 canonical.
- Customer 360 يجمع المعلومات في Tabs المعتمدة.
- المالية تعرض Workspace واحدًا واضحًا بلا تكرار Home/dashboard.
- QA على 375، 390، 430، 768، 1024، 1280، 1440+ بلا overflow غير مقصود.
- فحوص RTL للمال والجداول والـbreadcrumbs والpagination.
