# نموذج تشغيل الناقلين

## العقد الحالي

اعتمد ShipAudit منذ 2026-08-19 نموذج **تدقيق الفواتير فقط** للناقلين. مصدر العقد البرمجي هو `src/lib/carrierOperatingModel.js`.

- المتطلب الدوري الوحيد لكل ناقل متعاقد هو `invoice`.
- لا يُنشأ أي متطلب `cod_remittance` جديد، مهما كان تصنيف الملف التاريخي للناقل.
- مرحلة تحصيلات الناقلين في دورة المحاسب حالة مكتملة/غير مطلوبة، ولا تمنع الإقفال بسبب غياب ملف COD جديد.
- جداول أو أحداث أو ملفات COD القديمة تبقى دليلًا تاريخيًا للقراءة والتتبع، لكنها لا تُحسب كدفعات تشغيلية مطلوبة.
- الأرصدة التاريخية المتبقية تُصفّى من مساحة المالية فقط، ويجوز تسجيل تحويل يخص رصيدًا قائمًا. لا ينشئ النظام رصيد COD جديدًا عند اعتماد تدقيق فاتورة.

## حدود عدم الرجوع

لا يجوز إعادة ربط تصنيف `audit_with_cod` أو `audit_and_cod_separate` أو `cod_only` بمتطلبات شهرية جديدة دون قرار منتج صريح وتعديل هذا العقد واختباراته معًا. الإرشادات الأقدم التي تطلب جدول COD أسبوعيًا أو منفصلًا أصبحت تاريخية ولا تمثل التشغيل الحالي.

## ما تحميه الاختبارات

- جدول الفاتورة الصريح هو شرط الجاهزية الدوري.
- غياب أو فساد موعد الفاتورة يمنع الإقفال.
- اكتمال دورة المحاسب لا يعتمد رفع COD جديدًا.
- ملفات COD التاريخية لا تعيد فتح متطلب شهري، ولا يؤدي تكرارها إلى إنشاء دفعات تشغيلية.
