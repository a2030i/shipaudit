# بنية ShipAudit Pro

> آخر تحقق من المستودع: 2026-09-05 عند commit `94cbe1279690`. هذه الوثيقة تصف الكود الموجود، لا الحالة الحية للأنظمة الخارجية.

## هدف المنتج

ShipAudit Pro منصة تشغيل داخلية لشركة لوجستية/مالية تجمع تدقيق فواتير الناقلين، دورة المحاسب والإقفال، بيانات متاجر Lamha، التحصيل ومطابقة Zoho، المبيعات والحملات، والتقارير والإدارة. الواجهة ليست متجرًا عامًا؛ أغلب العمليات داخلية وتحكمها صلاحيات وتدقيق وحواجز مالية واتصالية.

## الوحدات الرئيسية

مصدر التنقل المرئي هو `src/lib/navigation.js`. التطبيق يعرض الرئيسية وسبعة مراكز عمل:

| الوحدة | أمثلة على المسؤولية |
|---|---|
| الرئيسية | ملخص التشغيل والتنبيهات |
| العملاء | المتاجر، Store 360، ملفات Lamha والتحصيل |
| المبيعات | العملاء المحتملون، النشاط والتوزيع |
| الحملات | الجماهير والقوالب وحملات التواصل |
| المالية | الموقف المالي، البنوك، Zoho، المصروفات والإيرادات |
| التشغيل | الناقلون، التدقيق، دورة المحاسب، المهام والمطالبات |
| التقارير | تقارير الأداء والمالية والتشغيل |
| الإدارة | الموظفون والصلاحيات والإعدادات والتكاملات والأتمتة |

المسارات الدقيقة والصلاحيات المرتبطة بها تتغير أسرع من هذه القائمة؛ افحص `src/App.jsx` و`src/lib/navigation.js` قبل تعديل routing أو IA.

## الصورة المعمارية

```text
المتصفح (React/Vite)
  ├─ Supabase Auth ───────────────> جلسة المستخدم
  ├─ PostgREST / RPC ─────────────> PostgreSQL + RLS
  ├─ Storage ─────────────────────> ملفات خاصة وسياسات وصول
  └─ Edge Functions ──────────────> service integrations / privileged workflows
                                      ├─ Zoho Books
                                      ├─ Lamha Employee API
                                      ├─ Hatif/Voxa وHudhud
                                      ├─ Tahseel وDaftra
                                      └─ Google/platform/webhooks

PostgreSQL
  ├─ بيانات تشغيلية ومحاسبية
  ├─ views/RPCs لعقود القراءة والكتابة
  ├─ سجلات تدقيق وidempotency
  └─ pg_cron/Vault لبعض المهام المجدولة
```

## طبقات التطبيق

### الواجهة

- `src/main.jsx`: نقطة التشغيل، `StrictMode`، حاجز الأخطاء، تهيئة عرض التاريخ بتوقيت السعودية، وترتيب CSS. ترتيب imports هنا جزء من السلوك المرئي.
- `src/App.jsx`: المصادقة، lazy loading، routing، shell، وربط الصفحات. `PageSlot` يبقي صفحات عديدة mounted ويغيّر ظهورها؛ لذلك effect يعتمد على route لا يجوز افتراض أنه يعاد بالـmount فقط.
- `src/pages/`: شاشات العمل، وبعضها كبير ويحتوي orchestration محليًا.
- `src/components/`: عناصر الواجهة المشتركة.
- `src/lib/`: عقود المجال، الخدمات، عميل Supabase، الصلاحيات، التصدير، parsing، والحواجز.

### الخلفية

- `supabase/migrations/`: تغييرات schema وRLS وRPCs وviews وcron على نحو تراكمي.
- `supabase/functions/`: Edge Functions مكتوبة لـDeno، وتنفذ التكاملات والعمليات ذات الامتياز الأعلى.
- لا يوجد backend تقليدي مستقل في المستودع؛ Supabase هو طبقة البيانات والخدمات الخلفية الرئيسية.

## تدفقات بيانات نموذجية

### دليل Lamha

1. وظيفة مزامنة تقرأ صفحات `/stores` بترتيب ثابت.
2. لا تعتمد اللقطة إلا عند اكتمال العدد وصحة الحقول المطلوبة.
3. تحفظ المرآة التشغيلية في `merchants` والتفاصيل في `lamha_store_profiles`.
4. القراءات المالية لا تستنتج قيمًا لم ترسلها Lamha؛ `null` يبقى غير معروف.

راجع `docs/architecture/lamha-data-authority.md` والكود في `supabase/functions/sync-directory/`.

### تدقيق الناقل ودورة المحاسب

1. تُرفع ملفات الناقل إلى storage خاص وتسجل metadata.
2. parser/audit engine يطبّق العقد والأسعار ويحفظ الشحنات المدققة.
3. إثبات عقد حديث مطلوب للاعتماد والتصدير.
4. دورة المحاسب تربط مراجعات الناقل، تصدير الأوزان، مطابقة AWB، مصادر Lamha، ثم الإقفال.

راجع `docs/architecture/carrier-operating-model.md` و`src/lib/accountingCycleStages.js` و`src/lib/auditProof.js`.

### المال والتحصيل

1. Zoho هو مصدر الأرصدة والفواتير المحاسبية في المسارات المحددة.
2. عقود RPC تجمع الموقف المالي وتربطه بهوية متجر ثابتة.
3. الواجهة تفصل المحاسبي عن القابل للتحصيل تشغيليًا وعن الرصيد المتبقي الصغير.
4. إرسال حملة أو تغيير حالة حساب ليس نتيجة تلقائية للقراءة أو المعاينة.

راجع `docs/architecture/financial-position-contract.md` و`docs/automation-operating-model-v2.md`.

## قرارات معمارية مثبتة

- Supabase هو منصة auth/data/storage/functions؛ الواجهة لا تحمل أسرار الخادم.
- واجهة الصلاحيات دفاع إضافي فقط؛ RLS/grants/function checks هي حدود التفويض.
- التكاملات ذات الأسرار تمر عبر Edge Functions، لا من المتصفح مباشرة.
- جداول وعقود مالية تستخدم integer minor units أو تحويلًا منضبطًا لتجنب أخطاء الكسور.
- الصفحات قد تبقى mounted بين التنقلات لتحسين الأداء والمحافظة على الحالة.
- التحديثات الخارجية الحساسة تتطلب idempotency وسجل نتيجة وفصل preview عن execution.
- ملفات Excel تقرأ بقيم raw في المسارات الحساسة، وتحديث الورقة يجب أن يراعي نطاق `!ref`.
- pagination على Supabase يجب أن يستخدم ترتيبًا فريدًا ثابتًا مع حلقات `.range()`.
- مفاتيح storage تُنشأ بصيغة ASCII حتى لو كان اسم الملف الأصلي عربيًا.

## حدود هذه الوثيقة

- هذه ليست قائمة routes أو tables كاملة؛ الكود هو المرجع للقوائم المتغيرة.
- توافق schema الحالي مع Production وحالة الوظائف المنشورة يحتاج تحققًا حيًا: `NEEDS_CONFIRMATION`.
